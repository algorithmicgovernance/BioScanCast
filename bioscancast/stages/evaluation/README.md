# BioScanCast Evaluation Stage

This folder evaluates probabilistic forecasts and tracks how they change across repeated forecast runs.

## Purpose

The eval stage is designed for forecasting systems that improve over time. In the current demo data, the timeline is driven by `forecast_date` when it exists; otherwise the eval stage assigns the forecast run date automatically when it loads the file.

The bundled mocks are set up as two runs:

- `2025-06-03` = the earlier v3 run with the four resolved questions
- `2026-06-29` = the later run with all eleven questions

## What it measures

The evaluation stage scores each question/source/run trio using metrics where lower is better:

- **Brier score**: probability error.
- **Log score**: negative log probability assigned to the true answer.
- **Accuracy error**: `1 - accuracy` so the direction matches the other metrics.
- **RPS**: Ranked Probability Score for ordered buckets.
- **Top probability**: the largest probability in the forecast.
- **Normalized entropy**: forecast uncertainty.
- **True probability**: probability assigned to the actual resolved outcome.

## Input format
 
Forecast files must contain at least:
 
- `question_id`
- `forecast_source`
- `forecast_version`
- `option`
- `probability`
- `forecast_date` (optional — see below)
If `forecast_date` is present, it's used as the timeline axis in the plots and time-series outputs. If it's missing, the eval stage falls back to assigning the date that matching with the version of other `.csv`.
 
CSVs are semicolon-delimited with a comma decimal separator (`sep=";"`, `decimal=","`), encoded as `cp1252`.
 
Example:
 
```csv
question_id;forecast_source;forecast_version;option;probability;forecast_date
q1;human;3;70-100;0,70;2025-06-03
q1;human;4;70-100;0,45;2026-06-29
```
 
## Perplexity forecasts and how runs accumulate
 
Perplexity forecasts are generated by `generate_perplexity_forecasts.py`, using `llm_baseline_forecasts.csv` as the option template (it defines which questions exist and which options each question has — the actual probabilities come from the Perplexity model).
 
Each time you run the script, it:
 
1. Reads the existing `perplexity_forecasts.csv` (if one exists) and finds the highest `forecast_version` already in it.
2. Queries Perplexity for a fresh probability distribution on every question in the template, using `forecast_version = last_version + 1`.
3. Stamps every new row with today's date as `forecast_date`.
4. **Appends** those new rows to the existing file rather than overwriting it, so the full run history stays intact.
If no `perplexity_forecasts.csv` exists yet, the first run starts at `forecast_version = 1`.
 
```bash
python generate_perplexity_forecasts.py --output bioscancast/stages/evaluation/mock_forecasts/perplexity_forecasts.csv
```
 
Pass `--overwrite` if you want to discard history and start a clean file at version 1 instead of appending.
 
The current eval flow does not depend on `bioscancast_forecasts.csv`.
 
## If `bioscancast_forecasts.csv` is added
 
There's no file by that name yet, but if/when the BioScanCast system's own forecasts are wired into this pipeline, the file should follow the exact same contract as every other forecast file so it needs no special-casing in the eval code:
 
```csv
question_id;forecast_source;forecast_version;option;probability;forecast_date
q1;bioscancast;1;70-100;0,62;2025-06-03
```
 
- `forecast_source` should be a fixed literal such as `bioscancast` (matching whatever value the eval scripts group/filter on), distinct from `human`, `llm_baseline`, and `perplexity`.
- `forecast_version` and `forecast_date` should follow the same append-only, auto-incrementing convention as `generate_perplexity_forecasts.py`: each new run gets `last_version + 1` and today's date, appended to the existing file.
- `option` values must match exactly (same buckets/strings) as the other sources for the same `question_id`, or the eval stage won't be able to compare them question-by-question.
- Probabilities within a `question_id` + `forecast_version` group should sum to 1.0 (the eval stage will normalize, but starting normalized avoids surprises in the metrics).
- Same delimiter/encoding conventions as the other files: `sep=";"`, `decimal=","`, `encoding="cp1252"`.
Once the file exists in `mock_forecasts/` (or wherever you point `--forecast-dir`), it will be picked up automatically — no code changes needed, since the eval stage discovers forecast files rather than hardcoding filenames, *provided* you also pass it explicitly if using `--forecasts` instead of `--forecast-dir`.
 
## How to run
 
From the project root:
 
```bash
python -m bioscancast.stages.evaluation.main
```
 
To run custom forecasts, pass one or more CSV files one by one:
 
```bash
python -m bioscancast.stages.evaluation.main --forecasts bioscancast/stages/evaluation/mock_forecasts/human_forecasts.csv bioscancast/stages/evaluation/mock_forecasts/llm_baseline_forecasts.csv bioscancast/stages/evaluation/mock_forecasts/perplexity_forecasts.csv
```
 
To run every forecast CSV in a folder, pass the directory:
 
```bash
python -m bioscancast.stages.evaluation.main --forecast-dir bioscancast/stages/evaluation/mock_forecasts
```
 
Use `--forecast-dir` when you want the eval stage to include everything in that folder automatically (this is also how a newly-added `bioscancast_forecasts.csv` would get picked up with zero code changes). Use `--forecasts` when you want to choose specific files yourself.
 

## Outputs

The pipeline writes results to `bioscancast/stages/evaluation/outputs/`.

Key files:

- `question_level_metrics.csv`
- `summary_metrics.csv`
- `summary_metrics_by_question_type.csv`
- `summary_metrics_over_time.csv`
- `metric_improvement_over_time.csv`
- `score_timeline_boxplots.png`
- `source_timeline_summary.png`
- `improvement_vs_v1.png`
- `question_heatmap.png`

### Main plots

- `score_timeline_boxplots.png` shows the latest score distribution for each source.
- `source_timeline_summary.png` shows the mean trajectory with standard-error bands and stars for the best source at each timepoint.
- `improvement_vs_v1.png` shows how much each run changes relative to the first run, with lower values indicating better improvement and stars marking the winning source at each timepoint.
- `question_heatmap.png` shows question-level evolution across runs.

## Interpretation

If the forecast learns over time, we expect the later run to move downward on the plots, because all metrics are shown in lower-is-better form.

Each source's runs are compared against its own earlier runs (via `forecast_version`/`forecast_date`), and sources are compared against each other at matching timepoints — so adding a new run for one source (e.g. re-running `generate_perplexity_forecasts.py`) doesn't require touching any other source's history.
